Human in the Loop MVP - Plan Matching Notes

Running notes for aligning the current implementation with the numbered MVP plan files.

Design Decisions

Finalize fails before mutation when required area pages are missing

The plan requires finalization to update affected area pages with the implementation delta. A missing affected area page is treated as invalid workspace state, not a recoverable omission.

hitl context --session can hydrate context without repeating the task

The documented session option now uses session metadata as authoritative input. The command still accepts explicit task/files and merges them with the session when supplied.

Site routes are exact public shapes

The local site now matches only the documented route shapes instead of treating extra URL segments as aliases for parent pages.

Persisted routing-index IDs are validated at workspace-validation time

Area and task ids loaded from routing-index.json must be safe single path segments before they are used to derive required route files.

Database notes live inside HITL content, not project db/

hitl db-docs writes the default architect-facing database scaffold to .humanintheloop/content/areas/data-spine/database.html. Project paths such as db/, prisma/, migrations, and backend code are evidence inputs, not the documentation output location.

Database documentation starts a focused HITL session

The command creates a data-spine session so an agent can fill the scaffold from actual schema, migration, seed, backend-code, and product evidence without relying on an automatic reverse-engineering pass.

Deviations

No intentional plan departures in this pass

The changes tighten behavior to match the existing plan rather than changing scope.

Tradeoffs

Preflight checks over best-effort finalize

Failing finalize before any session move avoids partial completion. This is stricter than silently skipping missing pages, but matches the plan's validation and no-silent-invalid-state rules.

Exact route matching over permissive aliases

Extra path segments now 404. This can reject accidental links that used to resolve, but it exposes broken generated links instead of masking them.

Validation errors over path-check side effects

Malformed routing-index ids are reported directly instead of becoming confusing missing-file checks for paths derived from invalid state.

Keep implementation-notes.html historical and use this file for current plan matching

The original notes file is preserved as the MVP handoff artifact and updated to stop overstating stale verification. Current plan-alignment decisions are captured here.

Scaffold over full automatic DB analysis

The first hitl db-docs implementation creates a constrained, evidence-inventoried HTML scaffold and session. It does not infer tables or relationships automatically because the MVP has no schema parser and must not invent human-facing database claims.

Explicit database route over arbitrary area-file serving

The site adds /areas/:id/database only. This keeps the local server narrow while making database notes first-class HITL content.
