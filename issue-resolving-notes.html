Human in the Loop MVP - Issue Resolving Notes

Running notes for resolving review findings after the MVP implementation.

Design Decisions

Make hitl init idempotent instead of refusing existing workspaces

Re-initialization should repair missing scaffold files without deleting existing sessions, claims, or mutable HTML state.

Escape every local-site render boundary

Session cards already escaped user input, but review queue and history pages are separate render boundaries. Claim fields and internal Git log text are now escaped before HTML composition.

Treat HITL workspace files as tool state, not project changes

hitl validate --changed now includes staged and untracked project files, but filters .humanintheloop/** so the tool's own generated workspace does not create false affected areas.

Require confident task matches before promoting related areas

Routing now only injects a task's required/recommended areas when the task itself clears a confidence threshold. This keeps weak lexical overlap like "api" or "retrieval" from making unrelated areas required.

Validate state-machine inputs at command boundaries

Review statuses and cleanup actions are now checked before persistence so typos cannot create machine-unreadable claim or stale-cleanup states.

Use branch/base evidence for validate --changed

Changed-file validation now combines committed branch changes, unstaged changes, staged changes, and untracked files, then excludes HITL's generated workspace.

Preserve human review states through finalize

Finalization now promotes only agent-draft claims to pending-human-review. Claims already reviewed by a human keep their status while their source path is moved to the completed session.

Make completed sessions immutable to mutating commands

hitl note and hitl cleanup now require an active session. Completed sessions remain historical output from finalize rather than accepting dangling draft cards later.

Use structured metadata for validation truth

Changed-file validation now reads session affected_areas and waiver-shaped metadata instead of treating arbitrary note body text as area coverage.

Keep visible cards and embedded metadata in sync

Review status changes now update both the visible data-status attribute and the corresponding metadata.cards[] entry.

Apply cleanup actions to matching old claims

Cleanup cards now update a matching old claim by id or title, including stale, superseded, needs-review, and kept-with-warning states. Supersede actions link the old claim to the cleanup card.

Use persisted file-area-map for validation gates

validate --files and validate --changed now union router-derived areas with areas matched from .humanintheloop/indexes/file-area-map.json, so workspace-specific path mappings remain enforceable.

Cleanup mutations must resolve a target first

Non-none cleanup actions now require --old-claim and fail before writing session cards if the supplied claim id or title cannot be found.

Keep claim relationship fields canonical

Review supersession now resolves the replacement through the claim index before writing superseded_by, stores the canonical replacement claim id, and clears stale relationship metadata when a claim is later reviewed into a non-superseded status.

Follow session page renames in internal history

Page-specific history now uses Git rename following so completed session pages still show the start, note, cleanup, and finalize commits that touched the session before it moved from active to completed.

Treat session ids as opaque identifiers

Session lookup now rejects forward and backward path separators before joining paths, so callers cannot use traversal-shaped ids to make completed sessions look active.

Validate generated site route targets

Workspace validation now checks generated area pages, task pages, agent-context pages, and decision pages derived from the routing index/default definitions, not only top-level indexes.

Use the file-area map consistently at session start

hitl start now uses the persisted file-area map when computing session affected_areas, matching the validation gate for custom mapped paths.

Keep explicit cleanup-none cards out of review

Finalize now promotes only draft claim cards to pending-human-review. Stale-cleanup none cards remain unindexed session evidence instead of becoming unreviewable pending cards.

Build the published CLI target during install/pack

The package now exposes dist through the package files list and runs npm run build in prepare, so git/package installs create the declared hitl bin target.

Finalize paths come from the looked-up session id

Finalize now uses the normalized session id from session lookup and rewrites embedded metadata back to that id, instead of trusting mutable HTML metadata for output paths or claim updates.

Context routing includes persisted file-map matches

hitl context now promotes areas matched by file-area-map.json into required context and preserves related decision context for default areas.

Prefer real branch bases over last-commit fallbacks

hitl validate --changed now checks remote and local default-branch refs before falling back to HEAD~1, so multi-commit local feature branches keep full coverage.

Reject cyclic claim supersession

hitl review --status superseded now rejects replacements that resolve to the same canonical claim id, preventing self-cycles in superseded_by.

Area empty states are replaced by real deltas

Finalizing the first implementation delta for an area now removes the default "no finalized memory" text before inserting the recent-memory card.

Validate persisted paths before filesystem writes

Claim source_html values and mapped area ids are now checked before they are joined into HITL content paths, so corrupted indexes cannot redirect review or finalize writes outside the content tree.

Context fails fast on malformed file maps

hitl context now ignores only the absence of an initialized file-area map. If the map exists but is malformed, the command reports the error instead of silently returning router-only context.

Cleanup actions preflight their target claim

Non-none cleanup now validates the target claim source path before adding the cleanup card, preventing failed cleanup commands from leaving persistent session evidence.

hitl context --session is session-aware

The documented session option now loads the session metadata, merges its task, files, and affected areas into context routing, and rejects missing or invalid session ids.

Return related decisions as routed context

Routing now emits declared related decision pages as recommended context so agents receive durable decisions like api-source-pull-model when source-ingestion is selected.

Validate persisted claim records before rendering

The claim index now validates required fields, statuses, string arrays, and safe source paths at read time. This makes hitl validate reject corrupted persisted state before review rendering can crash.

Preflight finalized affected areas before writes

Finalization now validates session affected_areas immediately after metadata parsing, before rewriting the active session, moving it to completed, or creating a delta page.

Use readiness polling for e2e server checks

The e2e test now allocates an available loopback port and waits for /api/status to respond before checking page routes.

Internal HITL Git is isolated from user signing policy

The tool-owned internal Git repository now sets commit.gpgsign=false so global user signing requirements cannot break local HITL history commits.

File-area-map shape errors fail closed

file-area-map.json entries must now map each known area to an array of string patterns. Typos such as a single string value are rejected instead of silently disabling validation coverage.

Tradeoffs

Preserve existing generated pages on re-init

Re-init will not overwrite existing mutable content pages. This favors data preservation over template refresh; template upgrades can be a separate explicit command later.

Add explicit agent-context routes instead of serving arbitrary files

The route table now exposes only the two advertised agent-context URL shapes. This keeps the MVP server narrow while fixing the broken generated links.

Threshold over hard-coded exclusions

The false routing positives were fixed by tightening the general relation-promotion rule rather than adding special cases for dashboard/API/provider wording.

Recommended context remains optional

Task-recommended areas are capped below the required threshold so validation does not force optional context. They still appear in the recommended group.

Self-building e2e over TypeScript runtime e2e

npm run test:e2e now builds dist/ before running the CLI workflow. This keeps the e2e test aligned with the published bin path instead of bypassing it through tsx.

Negative examples over global threshold changes

The routing false positives were fixed by teaching source-ingestion and API-surface contexts about each other's negative examples. This preserves valid add api endpoint routing while preventing provider API ingestion from loading API-surface context.

Union map and router results

File validation now treats the persisted file-area map as an additional source of required areas rather than replacing the router. This preserves semantic routing while making explicit workspace mappings authoritative for mapped paths.

Resolve relationships before mutating state

Supersession review now performs an extra claim-index lookup before mutation. This costs one local JSON read but prevents dangling review relationships and preserves canonical claim ids.

Default definitions plus routing-index ids

Generated route validation reads area/task ids from routing-index.json when available and uses default decision ids. This keeps customized area/task route checks aligned with the workspace without inventing a new decision-index format.

Prepare script over committed dist

The CLI keeps dist/ ignored in source control and relies on prepare plus package files metadata to build distributable output. This avoids committing generated JavaScript while keeping git installs functional.

CLI merge over router root awareness

The router remains deterministic and root-agnostic. The CLI merges persisted file-map areas at the boundary where workspace state is available, avoiding a filesystem dependency in the pure routing module.

Skip the current branch when checking local bases

Local main/master are only used as diff bases when they are not the checked-out branch. This preserves the existing HEAD~1 fallback for single-branch repositories while fixing local feature branches.

Avoid tracking-branch upstream as a validation base

A pushed feature branch often tracks origin/<feature>, not the integration branch. Using that ref as the diff base can resolve to HEAD, so the implementation now limits automatic branch bases to default-branch refs.

Simple empty-state removal over area-page rewrites

The area-page delta update removes only the generated empty-state paragraph before appending the new card. This avoids rebuilding customized area pages while eliminating contradictory text.

Fail closed on corrupted persisted routing state

Malformed file-area maps now stop context/session workflows instead of being treated as absent. This is stricter, but it keeps the pre-edit context gate consistent with later validation and finalize behavior.

Hydrate context at the CLI boundary

Session metadata is merged in cli.ts rather than the pure router. This keeps routing deterministic while making the command honor workspace state when a session id is supplied.

Read-boundary validation over render guards

Malformed claims are rejected by readClaimIndex instead of adding defensive checks only in the review queue renderer. This keeps every command that consumes claims on the same invariant.

Fetch readiness over stdout parsing

The e2e server wait probes the same local JSON endpoint used by the site smoke test. That avoids coupling the test to console text while still detecting bind failures before route assertions.

Repo-local Git config over command flags

Disabling commit signing in the internal Git config is applied whenever the internal repo is ensured. This covers init and later commands without repeating flags at every commit call.

Strict map validation over partial recovery

A malformed map value now fails the command rather than skipping only that area. This is intentionally strict because the map is a validation gate, not optional display metadata.

Open Questions

Template refresh command

Should a future command explicitly refresh default HITL templates while preserving user/session deltas?

Re-init policy

The current behavior is idempotent repair. If re-init should instead fail loudly when a workspace already exists, that should be specified as a future policy change.
