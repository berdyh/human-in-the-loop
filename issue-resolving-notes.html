Human in the Loop MVP - Issue Resolving Notes

Running notes for resolving review findings after the MVP implementation.

Design Decisions

Make hitl init idempotent instead of refusing existing workspaces

Re-initialization should repair missing scaffold files without deleting existing sessions, claims, or mutable HTML state.

Escape every local-site render boundary

Session cards already escaped user input, but review queue and history pages are separate render boundaries. Claim fields and internal Git log text are now escaped before HTML composition.

Treat HITL workspace files as tool state, not project changes

hitl validate --changed now includes staged and untracked project files, but filters .humanintheloop/** so the tool's own generated workspace does not create false affected areas.

Require confident task matches before promoting related areas

Routing now only injects a task's required/recommended areas when the task itself clears a confidence threshold. This keeps weak lexical overlap like "api" or "retrieval" from making unrelated areas required.

Validate state-machine inputs at command boundaries

Review statuses and cleanup actions are now checked before persistence so typos cannot create machine-unreadable claim or stale-cleanup states.

Use branch/base evidence for validate --changed

Changed-file validation now combines committed branch changes, unstaged changes, staged changes, and untracked files, then excludes HITL's generated workspace.

Deviations

No intentional spec departures

The planned fixes tighten the MVP behavior against the existing spec rather than changing scope.

No divergence from review findings

All six reported findings were implemented directly. The only additional change was filtering .humanintheloop/** from project changed-file detection after focused smoke testing showed it was required for --changed to work reliably.

Tradeoffs

Preserve existing generated pages on re-init

Re-init will not overwrite existing mutable content pages. This favors data preservation over template refresh; template upgrades can be a separate explicit command later.

Add explicit agent-context routes instead of serving arbitrary files

The route table now exposes only the two advertised agent-context URL shapes. This keeps the MVP server narrow while fixing the broken generated links.

Threshold over hard-coded exclusions

The false routing positives were fixed by tightening the general relation-promotion rule rather than adding special cases for dashboard/API/provider wording.

Recommended context remains optional

Task-recommended areas are capped below the required threshold so validation does not force optional context. They still appear in the recommended group.

Open Questions

Template refresh command

Should a future command explicitly refresh default HITL templates while preserving user/session deltas?

Re-init policy

The current behavior is idempotent repair. If re-init should instead fail loudly when a workspace already exists, that should be specified as a future policy change.
